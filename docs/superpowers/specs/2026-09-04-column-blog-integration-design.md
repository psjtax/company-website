# 세무소식 · 네이버 블로그 연동 설계

작성일 : 2026-09-04
정한 사람 : 지윤 대리님 / 만드는 사람 : 빵자

## 왜 만드나

세무소식 페이지(`column/`)를 손으로 채우지 않고, 사무소 네이버 블로그의
**'세금이야기' 분류 글**을 자동으로 가져와 채운다.
대리님이 글을 따로 주실 필요도, 빵자에게 부탁하실 필요도 없어야 한다.

인스타그램(@taxpsj) 연동은 **이 문서 범위 밖**이다. 2단계로 따로 진행한다.
(2026-09-04 기준 게시물 1건·팔로워 0명이라 지금 붙여도 보여줄 것이 없다)

## 확인해 둔 사실

직접 받아보고 확인한 것들이다. 다시 조사하지 말 것.

| 항목 | 확인 결과 |
|---|---|
| RSS 주소 | `https://rss.blog.naver.com/tax5868.xml` — 200, 약 70KB |
| 글 수 | 36건. `세금이야기` 34건 / `사무소 소개` 2건 |
| 분류 구분 | RSS `<item>` 안에 `<category>` 가 있어 그대로 거르면 된다 |
| 글에 담긴 정보 | `author, category, title, link, guid, description, pubDate, tag` |
| `description` | 전문이 아니라 **약 350자 발췌** + `<img>` 1개 |
| 날짜 범위 | 가장 최근 2024-11-07, 가장 오래된 2024-05-08 (약 1년 10개월 멈춰 있음) |
| 본문 페이지 | `https://blog.naver.com/PostView.naver?blogId=tax5868&logNo={번호}&redirect=Dlog&widgetTypeCall=true&noTrackingCode=true&directAccess=false` — 200 |
| 본문 영역 | `<div class="se-main-container">` 안에 들어 있다 |
| 본문 분량 | 한 글에 글자 수천 자. 글자 위주라 읽을 만하다 |
| 사진 주소 | `postfiles.pstatic.net`. `data-lazy-src` 에 들어 있다 |

### 사진 — 직접 불러오기는 막혀 있다

| 어떻게 불렀나 | 결과 |
|---|---|
| 출처(Referer)를 `psjtax.co.kr` 로 보내기 | **403** |
| 출처를 아예 안 보내기 (curl) | **200**, 239KB PNG |
| 브라우저에서 `referrerpolicy="no-referrer"` | **403** — 우회 안 됨 |

브라우저로는 어떻게 해도 막힌다. **서버가 미리 받아서 우리 사이트에 두는 수밖에 없다.**

## 어떻게 만드나

```
네이버 블로그 (tax5868)
      │  ① RSS 로 새 글 목록
      │  ② <category> 가 '세금이야기' 인 것만
      ▼
   글 하나하나
      │  ③ PostView 에서 본문 글자
      │  ④ 사진 내려받아 크기 줄여 저장
      ▼
 column/index.html  (+ column/img/)
      │
      └─ GitHub Actions, 하루 두 번 (세무뉴스와 같은 시각)
```

세무뉴스(`tools/update_news.py`)가 이미 같은 길을 닦아 두었다. 구조를 그대로 따른다.

### 파일 구성

| 파일 | 역할 |
|---|---|
| `tools/update_column.py` | **새로 만듦.** 받아오기 · 고르기 · 사진 저장 · HTML 갈아끼우기 |
| `column/index.html` | 목록과 읽는 창. `<!-- 글 여기부터 --> ~ <!-- 글 여기까지 -->` 사이만 자동으로 바뀐다 |
| `column/img/` | **새로 만듦.** 내려받아 크기 줄인 사진 |
| `.github/workflows/news.yml` | 실행 단계 한 줄 추가 |
| `style.css` | 읽는 창 안 사진 스타일 조금 |

### 사진 처리 규칙

- 파일 이름은 **원본 주소를 짧게 줄인 값**으로 정한다 (같은 사진을 두 번 받지 않게)
- 이미 `column/img/` 에 있으면 **건너뛴다**
- Pillow 로 **가로 900px 이하**, JPEG 품질 80 정도로 줄인다 (한 장 60~80KB 목표)
- 한 글에 사진이 아주 많으면 앞에서부터 **최대 12장**까지만
- 글에서 지워진 사진은 바로 지우지 않는다 (지우는 건 나중에 손으로)

### 화면

- **목록** — 제목만. **날짜는 보여주지 않는다** (대리님 결정: 2024년 글이라 날짜가 오히려 걸림)
- **누르면** — 세무뉴스와 같은 읽는 창에 **글 + 사진**
- **창 아래** — `블로그에서 보기` 링크 (원문으로 이동)
- 글이 하나도 없으면 "첫 번째 글을 준비하고 있습니다" 안내 (이미 만들어 둠)

## 잘못됐을 때

| 상황 | 어떻게 |
|---|---|
| RSS 를 못 받아옴 | **아무것도 바꾸지 않고 끝낸다.** 기존 화면 유지 |
| 어떤 글의 본문을 못 가져옴 | RSS `description` (350자 발췌) 로 대신한다 |
| 사진 한 장이 안 받아짐 | 그 사진만 빼고 나머지는 정상 진행 |
| 사진 크기 줄이기 실패 | 원본을 그대로 저장하지 말고 그 사진은 건너뛴다 |
| 바뀐 내용이 없음 | 커밋하지 않는다 (세무뉴스와 같음) |

상대 서버에 부담을 주지 않도록 글 사이에 **0.25초씩 쉰다.** (세무뉴스와 같음)

## 확인 방법

1. 손으로 `python tools/update_column.py` 를 돌려 결과를 본다
2. `python -m http.server` 로 띄워 목록·읽는 창·사진이 제대로 나오는지 본다
3. 사진이 정말 우리 사이트에서 나오는지(네이버 주소가 아닌지) 확인한다
4. `one_file.py` 로 미리보기를 만들어 **대리님께 먼저 보여드리고**, 확인받은 뒤 올린다

## 정하지 않고 남겨둔 것

- 목록이 34건이라 한 화면에 길다. 쪽 나누기(페이지)가 필요한지는 **화면을 보고 정한다**
- 글 아래 안내 문구("일반적인 안내입니다…")를 남길지는 대리님 확인 대기 중
- 인스타그램 연동 (2단계)
